# DeviceHost / WindowsProtect

WindowsProtect is a family-PC anti-scam protection project. DeviceHost is its private security-health dashboard.

## Final architecture

- **DeviceHost (Vercel + Supabase):** security health, online/offline state, Defender, Firewall, SmartScreen, installed-app count, unauthorized remote-tool detection, security events.
- **MeshCentral 1.2.6:** separate authenticated remote-support control plane.
- **WindowsProtect endpoint:** reports security telemetry to DeviceHost and uses the official MeshCentral agent for remote support.
- **Temporary support:** MeshCentral guest/device share with a default 120-minute expiry and manual revoke.
- **No DeviceHost remote shell:** interactive remote control stays inside MeshCentral.

## Why MeshCentral

MeshCentral is free/open-source and provides persistent managed devices, browser-based remote desktop, files/terminal, device groups and guest sharing without requiring a separate permanent remote-access password for each PC.

## Repository layout

- `app/` - DeviceHost dashboard and APIs
- `supabase/` - DeviceHost database migrations
- `meshcentral/` - pinned MeshCentral server deployment
- `windows-agent/` - WindowsProtect endpoint test sources
- `.github/workflows/` - Windows and DeviceHost build verification

## Deployment order

1. Deploy DeviceHost.
2. Apply the Supabase monitoring and MeshCentral migrations.
3. Deploy the MeshCentral server using `meshcentral/`.
4. Create the first MeshCentral administrator, enable 2FA and create the `Family PCs` device group.
5. Download the Windows agent generated by that exact MeshCentral device group.
6. Package/test WindowsProtect on a disposable Windows machine.
7. Verify reboot persistence, DeviceHost telemetry, remote control, guest-share expiry/revocation and clean uninstall before family deployment.

## Important

The final MeshCentral Windows agent is server-specific. It cannot be generated before the MeshCentral server and device group exist.

Do not deploy an unverified WindowsProtect build to a family PC. First validate it on the disposable Kamatera test machine.


## Installer configuration

Set `MESHCENTRAL_AGENT_URL` in Vercel to the server-generated Windows x64 agent URL for the approved `WindowsProtect Family` MeshCentral device group. The one-time setup-code redemption endpoint returns this URL only after a valid short-lived code is redeemed.

## Managed removal protection (0.5.9-test)

The installer confirms service hardening before reporting installation complete. Protection and its approved support agent stay visible as WindowsProtect components. Their normal Control Panel removal option is disabled, and service, installation-file and activation-setting ACLs give SYSTEM write/control access while administrators retain read/query access. Service failure recovery and periodic permission reapplication resist ordinary stop/disable/delete attempts. The authenticated dashboard removal worker runs as SYSTEM and can still remove the components.

Updates require the already mandatory real Windows password check. The installer then uses administrator ownership/restore privileges to open a ten-minute maintenance window, which does not switch off existing remote-tool blocking or extend activation. It confirms fresh hardening after the update. Administrators can use those same Windows privileges to override this protection manually; recovery-mode access, administrator/SYSTEM compromise and operating-system reinstallation remain outside this guarantee. This is managed removal resistance, not an invisible or undeletable installation.

Apply the lifecycle constraint section in `supabase/devicehost_monitoring.sql` to the DeviceHost database. It retains existing states and accepts setup deadlines and nonce-bound removal requests. It makes no changes to protection-status/security-posture constraints or database privileges.

## Blocking, alerts, controlled exceptions and installer delivery (0.5.16)

Known remote-tool process aliases are blocked on the independent one-second policy loop. A separate identity scan checks executable product/description/original-name resources to catch ordinary renamed binaries without holding up deadline enforcement or telemetry. Related services are disabled/stopped, including RustDesk. The approved support executable is exempt only at its registered, restricted installation path. Version-resource identity is an additional layer, not an unforgeable signature: stripped/forged metadata, unknown tools, browser-only access and administrator/SYSTEM compromise remain limitations.

The user-facing installer has no test-build label or dashboard-approval wording. A pending installation reports its setup-period deadline accurately; active upgrades remain protected. Dashboard messages use Windows system colors, standard warning/information/error icons, a native OK button and a scrolling text area in compact/standard/large sizes. The title bar always identifies WindowsProtect.

The Windows workflow publishes an immutable prerelease installer, service agent and checksum manifests only after Microsoft Defender scans every distributed executable. Version 0.5.16 retains remote-tool blocking, temporary UltraViewer access, dashboard messages and website opening, automatic verified updates and managed removal. It records blocked unauthorized remote-access processes and services, warns the Windows user locally, and shows an urgent dashboard alert with the affected PC, tool and time. The public page creates a private encrypted share link valid for 24 hours. Opening it downloads a ZIP with unchanged installer bytes and a one-time setup-code sidecar valid for four hours. Customer, device label, assigned support agent and code load automatically. Windows-password verification is requested by default, with an explicit skip option when the password is unavailable; it is immediately forgotten and never stored or uploaded. Installer signing is not currently configured.

The public installer asks the customer to choose Koko or Ashu. Enrollment writes that selection as an audit event, and DeviceHost shows it in the device table without a database migration. Protected PCs running 0.5.11 can receive a dashboard-authorized UltraViewer exception for 30 minutes. The expiry is stored both by DeviceHost and locally under SYSTEM-only settings; UltraViewer is blocked again locally at expiry even if the PC loses internet access. Old agents cannot create a misleading exception state.

Version 0.5.16 uses a permanent fixed-purpose update component instead of generating a PowerShell update script. The agent authenticates with its existing device token, accepts only a newer semantic version from the fixed DeviceHost endpoint, restricts downloads to this repository's versioned HTTPS release path, verifies the published SHA-256 hash, and rolls back if the replacement service does not start. It also lets queued 0.5.14 uninstall requests wait for the fixed automatic update before resuming, so no manual reinstall is required. Later verified agent and blocking-policy updates do not require reinstalling the setup application.

`/download` is a public self-service page. A customer enters their name, phone number and email; the PC name is optional. The server validates the form, rate-limits both the source and a keyed contact fingerprint, verifies the published installer hash, then returns a private no-store ZIP with a 30-minute one-time setup code. Raw phone and email values are not placed in the package or setup-code table. The dashboard and all admin routes remain protected by Basic authentication.
